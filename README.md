# AI 产品经理入门 · 学习平台

给零基础、想入门 AI 产品经理的人认词用的。56 个术语分三层:入门(把词认全)、进阶(智能体怎么干活)、
深入(产品经理的取舍)。每个词用人话讲一遍,不懂就在下面接着问,导师会边答边记你卡在哪,
下次讲新词时先照顾你的路子。

    python3 app.py            # http://127.0.0.1:8440

## 结构

    terms.json   术语表。一个词一条:一句话、讲解、比喻、产品例子、常见误解、前置、相关、自测题。
                 人写的,是这个项目唯一的「资产」。
    memory.py    学员记忆。SQLite,在 data/learn.db。进度、对话、信号、画像、补充讲解缓存。
    tutor.py     三种模型调用:追问、按画像重讲、归纳画像。
    serve.py     标准库 HTTP,只监听本机。
    provider.py  从选题台原样搬来的供应商层,自己没有 config.json 时回退读上一级的。
    app.html     单页。左导航 + 右内容,Notion 那种素的样子。

## 设计约束

- **术语表不依赖模型。** 没有 key 也能把 56 个词看完、做完自测。模型只用在三处:追问、
  按画像重讲、归纳画像。这样即使哪天不想花钱,平台的主体还在。
- **困难类型和讲法类型是固定词表(7 + 6),模型只能从里面选。** 让模型自由打标签,两个月后
  画像是一堆互相不认识的词,没法聚合、没法驱动推荐。词表在 `memory.py` 顶上,要加就加在那儿。
- **每一轮追问同时产出回答和信号。** 不单独跑一次「评估学员」的调用 —— 一次调用两件事,
  成本减半,而且模型刚回答完最知道学员卡在哪。
- **画像不是每轮重写。** 信号先攒着,每 6 条让模型归纳一次(旧画像 + 近期信号 → 新画像,
  ≤120 字)。补充讲解按 (词, 画像指纹) 缓存,画像没变就不重新生成。
- **推荐是规则,不是模型。** 卡住的先回头 → 前置齐了才推 → 薄弱类别加权 → 顺着刚学会的走 →
  同分先低级别。规则在 `memory.recommend()`,一眼能看懂,改起来不用测提示词。
- **记忆对学员透明、可清空。** 「我的画像」页把每一条信号、每一版画像原样列出,一键清空。
  记了什么不透明,用户不会信任;记错了改不掉,用户会放弃。

## 加一个词

在 `terms.json` 里照着任何一条抄。`prereq` 和 `related` 填别的词的 `id`,启动时不检查,
但 `python3 -c "import serve"` 之后调 `serve.api_term` 时不存在的 id 会被静默跳过。
